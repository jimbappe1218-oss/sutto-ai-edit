# スッと検査（仕上げ検査）

編集した動画を「できました」と報告する前に、必ずこの検査を通します。数字で分かることは測り、数字で分からないこと（テロップの見た目）は、コマ一覧の画像を自分の目で見て確かめます。

スクリプト: `SKILL_DIR/scripts/kensa.py`（`SKILL_DIR` は、この SKILL.md があるフォルダ）。

## 手順

1. **実行する**
   ```bash
   python3 "SKILL_DIR/scripts/kensa.py" "完成.mp4" --target youtube
   ```
   - ショート動画は `--target short`
   - テロップを入れた動画は `--telop "テロップ出力.mp4.telop_report.json"` を付ける（テロップが出ているコマを並べる）。報告ファイルは `sutto-telop` と `sutto-ugoki captions` のどちらも、出力した動画と同じ場所に作る。BGM を入れたあとでも時刻は同じなので、そのまま使える
   - 編集前の素材があれば `--before "元の素材.mp4"` を付ける（長さ・音量の変化が出る）
2. **`RESULT_JSON` を読む。** `verdict` が「問題なし」「注意あり」「要修正あり」のどれか、`issues` に何が出ているか。
3. **コマ一覧の画像を Read で開いて、目で見る。** 場所は `RESULT_JSON` の `sheet` → `png`（ファイル名は `元の名前_検査.png`）。次の点を確かめる:
   - テロップが画面の端で切れていないか
   - テロップが顔・商品・大事な文字に重なっていないか
   - 文字が背景に埋もれず読めるか、改行位置がおかしくないか
   - 誤字が残っていないか
4. **「要修正」があれば直して、もう一度検査する。** 直せないものは理由をつけて報告する。
5. 利用者への報告には、`verdict`、主な数字（長さ・解像度・LUFS・ピーク）、見つけた点、コマ一覧の画像の場所を入れる。

## 判定の基準

| 項目 | 要修正 | 注意 |
|---|---|---|
| 音の大きさ | 目標（−14 LUFS）から 2 LU 超のずれ | 1 LU 超のずれ |
| ピーク | −0.3 dBTP より高い | −1 dBTP より高い |
| 色形式 | yuv420p 以外（再生できない環境がある） | — |
| 真っ黒なコマ | 途中にある | 冒頭・末尾にある |
| 長い無言 | — | 2 秒以上（`--silence` で変更） |
| 映像の静止 | — | 3 秒以上（静止画を使っているなら問題なし） |
| 映像と音声の長さ | — | 0.15 秒超のずれ |
| ショート（`--target short`） | 9:16 でない／3 分超 | 1080×1920 未満／60 秒超 |
| 本編（`--target youtube`） | — | 1080p 未満／縦長 |

目標の大きさは `--lufs -16` のように変えられる。基準を当てはめたくないときは `--target none`。

## 注意

- 音は鳴らさない。聞こえ方（声の明瞭さ、BGM の好み）は数字では決められないので、最終確認は利用者に頼む。
- コマ一覧は既定で 12 枚。長い動画で細かく見たいときは `--frames 24`。
- 検査結果は `元の名前_検査.json`、コマ一覧は `元の名前_検査.png` に保存される（`--out フォルダ` で保存先を変えられる）。同じ名前の動画をもう一度検査すると、前の結果は上書きされる。
